\subsection{Frontend}\label{sec:frontend}
The web interface is a Next.js~16 (App Router) application written in TypeScript with React~19 and Tailwind~CSS~4. All pages are client components that call the APIs directly from the browser. The landing page (\code{/}) offers \emph{Log in} and \emph{Register}, both handled by Keycloak's hosted pages. The authenticated area comprises \code{/movies} (catalogue grid with search and sorting, topped by \emph{Recommended for you}), \code{/movies/[id]} (details, IMDb/TMDB links, \emph{Mark as watched}, \emph{Watch later}), \code{/recommendations} (\emph{Ask AI}), \code{/users} (username prefix search) and \code{/users/[id]} (favourite genres, watched movies, following and followers tabs, \emph{Follow}, and genre editing and the watchlist on one's own profile, \code{/users/me}).

Authentication uses \code{keycloak-js} with the public \code{movies-frontend} client, authorization code flow and PKCE (S256). A route-group layout wraps every authenticated page in an \code{AuthGate} that initialises Keycloak with \code{login-required}, redirects anonymous users to the login page and back, and immediately requests \code{/profiles/me} so that the user's profile is created on first login. The token is kept only in memory; before every request, \code{lib/api.ts} calls \code{updateToken(30)}, refreshing it if it expires within 30\,s, and maps API errors to typed exceptions.

Lists use a generic \code{useInfinitePages} hook: an \code{IntersectionObserver} on a sentinel element fetches the next page (24 movies) ahead of the viewport, guarding against duplicate requests. Search and sort state lives in the URL query (e.g.\ \code{?q=batman\&sort=newest}), so reloads and the back button preserve it. API and Keycloak locations are \code{NEXT\_PUBLIC\_*} variables inlined at build time. Locally the frontend and the APIs are on different origins, so each Quarkus service whitelists the frontend origin via CORS; in the cluster the image is built with relative addresses (\code{/api}, \code{/auth}), so the browser sees one origin and the same image works at any address.

Recommendations take minutes, so the interface never waits for them. \emph{Recommended for you} is the first row of \code{/movies}: the first set is requested on the user's first visit, and the row fills in, and updates itself, when the background agent finishes a new set. \emph{Ask AI} sends a free-text request, disables the box while one is being prepared, lists the last five answers, and the user can leave the page: the browser holds a server-sent-events connection to the Recommendation API, and a notification says when a result is ready or why it failed.
