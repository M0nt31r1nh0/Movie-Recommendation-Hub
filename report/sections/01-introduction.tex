\section{Introduction}\label{sec:intro}

The PSIA project asks for a realistic, tiered, microservices-based application with AI components, deployed on a public cloud with Infrastructure as Code (IaC) end to end, where Terraform creates the virtual machines, Ansible configures them, and a \emph{self-hosted} Kubernetes cluster runs the application (managed offerings such as GKE are not allowed). The system must be monitored, and extended with one advanced feature.

Our application is a \emph{Movie Recommendation Hub}. Users register and log in through Keycloak (OpenID Connect~\cite{oidc}), keep a profile with their favourite genres, watched and saved movies and the users they follow, browse and search about 45\,000 movies from The Movies Dataset~\cite{banik2017movies}, and view other users' profiles. A language model served by Ollama recommends movies in the two ways the statement requires, \emph{on demand} from a request the user types (``a horror movie from the 80s'') and \emph{proactively} through a background agent that prepares and caches a set per profile, so users see fresh recommendations as soon as they log in. Each backend service owns its own PostgreSQL database~\cite{richardson-dbps}.

The system runs on Google Cloud (\code{europe-west4}) on a kubeadm cluster of three VMs, monitored with Prometheus~\cite{prometheus} and Grafana. As advanced feature we chose \emph{persistent state}, so all VMs can be stopped and restarted, or destroyed and recreated, without losing any application state.
