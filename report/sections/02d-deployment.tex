\subsection{Deployment and Operations}\label{sec:deployment}
\subsubsection{Local} The whole system runs in Docker as three Compose projects on one network, one for the infrastructure (databases, Kafka, Ollama and a job that downloads the models, Keycloak), one for the four services and one for the frontend. One multi-stage Dockerfile builds any service, and the same images serve the cloud. A \code{justfile} starts the projects in order and waits for each to be healthy, since Compose cannot order separate projects.

\subsubsection{Kubernetes on GCP} Everything is driven from a management container holding Terraform, Ansible, \code{kubectl} and \code{gcloud}. Terraform creates, in a separate stack that outlives the VMs, one data disk per worker and a static IP (Section~\ref{sec:advanced}), and then a VPC, firewall rules and three Ubuntu~24.04 VMs in \code{europe-west4-b}, a control plane (\code{e2-standard-2}) and two workers (\code{e2-standard-4}). Four Ansible playbooks then prepare the nodes (containerd, kubeadm), create the cluster with Calico as pod network, install the platform with Helm (the Strimzi Kafka operator, kube-prometheus-stack and the volumes), and deploy the application from manifest templates, with a PostgreSQL StatefulSet per database with a metrics sidecar, Kafka with three brokers and topics replicated three times, Ollama, Keycloak, the four services with health probes, and NetworkPolicies so that each database accepts only its own service. The services, the frontend, Keycloak, Ollama and NGINX run as Deployments, which guarantee that the number of pods asked for (one each here) is always running, so a pod that crashes, is deleted or is lost with its node is recreated, and a container that fails its liveness probe is restarted, with no manual step. Each Deployment and database sits behind a Service, a stable name and address inside the cluster that forwards to whichever of its pods are ready, so NGINX and the other services keep reaching it while its pods are replaced and change address, and replicas can be added without changing any client. NGINX runs on the worker that owns the static IP, and every other port stays closed to the Internet. No password is in git or in an image. On the first run Ansible generates random ones (for the four databases and for Keycloak's and Grafana's admins, and the client secrets of the two service accounts, which replace the realm's development secrets), keeps them in a git-ignored folder of the management machine, and stores them in Kubernetes Secrets, from which each pod receives only the keys it needs as environment variables. NGINX's TLS key is in a Secret of its own. Every step can be re-run without changing what is already right. A deployment from nothing takes about 25 minutes:

{\footnotesize\begin{verbatim}
just images docker.io/<user> v1 # push images
just mgmt-start && just mgmt    # mgmt shell
just all              # VMs, cluster, app
just stop | start | destroy
\end{verbatim}}
\noindent The repository's \code{README.md} and \code{infra/README.md} give every step, including the one-time Google Cloud setup.

\subsubsection{Monitoring} Prometheus scrapes, every 15\,s, each service's Micrometer metrics, the databases' and NGINX's exporters, Kafka's lag and the nodes. Beyond the standard HTTP and JVM metrics, each service records application metrics, such as searches and whether they found anything, profile changes, recommendation requests by kind and outcome (including those answered without the model), the time from a request to its answer, jobs waiting in Kafka, and each model call's duration and tokens, since Ollama has no metrics of its own. A provisioned Grafana dashboard, \emph{Movies}, is built on them, and is served at \code{/grafana}, while Prometheus itself is not public. Fluent Bit, on every node, collects each container's log, and Loki aggregates them for 7~days, so they can be searched in Grafana across pods and restarts. Prometheus also evaluates our alert rules (Table~\ref{tab:alerts}), besides kube-prometheus-stack's defaults, and Grafana lists them by state. There is no Alertmanager, so alerts are not sent anywhere.
