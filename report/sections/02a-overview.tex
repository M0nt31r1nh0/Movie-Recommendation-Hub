% 02a-overview -- follows \section{System Design and Architecture}
The system follows the tiered architecture of the specification (Fig.~\ref{fig:architecture}, Table~\ref{tab:components}). The \emph{frontend} is a Next.js web application. In the cluster an NGINX reverse proxy is the only public entry point. It terminates TLS and routes \code{/} to the frontend, \code{/api/*} to the services, \code{/auth/} to Keycloak and \code{/grafana/} to Grafana. The \emph{backend} has four Quarkus services, namely the Movies API (catalogue, search, search by meaning), the Profiles API (genres, watched and saved movies, follows), the Recommendation API, which stores recommendations and queues the work, and the recommendation worker, which takes that work from \emph{Apache Kafka} and queries the \emph{inference engine}, Ollama. The \emph{data tier} is PostgreSQL~16, one instance for each service that keeps data plus one for Keycloak. Services read each other's data only through their APIs, so each can change its schema, be scaled or be restored without touching the others, and a failure or load spike in one database stays there. Prometheus and Grafana form the \emph{monitoring server}.

The browser obtains a short-lived JWT from Keycloak (authorization code flow with PKCE) and sends it to every API, which checks its signature, issuer and its own audience, so tokens issued for other clients are rejected. The recommendation service and the worker call other services as themselves, with Keycloak service-account tokens (client credentials).
